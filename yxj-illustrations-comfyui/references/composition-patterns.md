# 结构类型与原创隐喻

> 取自 ian-xiaohei-illustrations 的 `composition-patterns.md`，按圆点规则改造：
> 物件是主体、人物最多一次且 20–25% 图高、可以不出人。原文里的「小黑」读作「圆点」。

## 先选结构，再想画面

一张图只选**一种**结构，不要混。选完再决定圆点出不出场。

| 结构 | 适合 | 画法 | 要不要人 |
| --- | --- | --- | --- |
| **Workflow 流程** | 输入→处理→输出、内容生产、自动化链路 | 左输入、中间怪机器处理、右输出；橙色箭头一条主流向 | 一般是（人操作中间那台机器） |
| **系统局部** | 信息来源、过滤器、数据库、renderer、agent 局部 | 只画 3–5 个核心模块，不画全局 | 可选（人只碰其中一个模块） |
| **前后对比** | 混乱/有序、手动/自动、分散/收拢 | 左乱、右稳、中间橙色箭头；两边**用物件状态**区分，不要左右各站一个人 | 一般不要，或只在「之后」那侧画一个 |
| **状态演变**（原「角色状态」改造） | 用户痛点、工具太多、信息焦虑、卡住到跑起来 | 2–4 个**物件**状态并列（三个抽屉越开越大、纸带从打结到顺直），每个状态一处短批注 | **不要人**（原文按格画小黑，这里改成物件） |
| **概念隐喻** | 内容工厂、信息仓库、脑内黑盒、自动日报 | 一个大的怪物件/机器，少量输入，一个输出；要有一个记忆点 | 可选（人在机器边做一个动作） |
| **方法分层** | 方法论框架、能力栈、内容系统分层 | 一层层盒子堆起来，不要正式金字塔；人可以在旁边搬砖 | 可选 |
| **地图路线** | 从想法到上线、用户路径、学习路线 | 一条弯曲路径 + 3–5 个节点，不要均匀刻度 | 可选（人在路上走/牵线） |
| **小漫画分镜** | 失败到成功、真实过程、吐槽 | 2–4 格，每格一个动作 | **默认不要**（分镜最容易变成多个圆点；要分镜就每格用物件，不用人） |

## 原创隐喻生成法

每次都从当前文章重新发明隐喻，不能照搬旧图。

### 三步

1. **抽象概念 → 物理动作**：卡住、漏掉、变重、分拣、沉淀、发酵、开门、折叠、拆包、回流。
2. **系统结构 → 低科技物件**：坏掉的机器、纸箱、抽屉、水管、邮筒、怪表盘、秤、井、梯子、晾衣绳、奇怪工位。
3. **决定人物角色**：需要一只手去推动 → 圆点做那个动作；结构自己会说话 → 不画人，把物件画清楚。

### 物件池（一次只选 1–2 个，不要堆满）

纸箱、抽屉、旧机器、漏斗、秤、邮筒、门、井、梯子、水管、线团、闸门、转盘、黑盒、打孔器、压面机、晾衣绳、怪工位。

### 圆点动作池（要人时选一个，动宾写清）

拉、扛、塞、捞、压、称、缝、剪、拧、守、推、接、拆、标记、回收、补漏、扶梯。

动作要服务核心意思，不要为了怪而怪。

## 元素组织（画之前的检查）

1. **主物件 3–5 个**，其余删掉。超过 5 个就是密集节点网。
2. **物件比人大**：主线物件占画面 40–60%，圆点约 20–25% 图高。
3. **一条流向**：入口在左或上，出口在右或下，中间一条橙色箭头，不要一层层箭头。
4. **一块安静区域**：留 ≥35% 空白，最好集中在一边，专门放批注。
5. **多状态用物件**：三个深浅不同的抽屉 ≠ 三个人。

## 反复刻规则

不要默认复刻旧案例。旧图（小黑仓库 examples、本技能已出过的图）只作风格校准：线条密度、留白、颜色克制。

除非用户明确说「照这张 / 复刻这个构图」，否则不要直接复用这些旧构图：

- 传送带两个断点
- 人在内容机器里拉判断杆
- 人变漏斗分拣流量/信任/转化
- 切素材鱼
- 牵承接路径
- 拉三层信息源
- 三个人分别拿喇叭/搭桥/开门
- 盖章话术工具箱
- 举牌看常见坑路径

同类主题也要换新隐喻。例如「承接路径」不一定画路线，可以画人把内容尾巴接到门把手；「一鱼多吃」不一定画鱼，可以画一个纸团被压成几种形状。
